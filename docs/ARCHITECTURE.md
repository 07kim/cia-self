# 技術設計

- React、TypeScript、Viteを使用する。
- 画面状態は`home / scan / cart / lock / history`を基礎とし、読取処理は画面遷移と分離した状態機械で管理する。
- 取引と商品明細は`src/data.ts`の固定データとし、検索前にNFKC正規化、空白除去、小文字化を行う。
- 四隅操作と放置復帰はブラウザ内で完結する。四隅は`pointerdown`と専用の進行参照で連続タップを取りこぼさず、通常メニューのクリックとは分離する。最初の左上から1.5秒の単一タイマーを開始し、時間切れまたは誤入力で進行をリセットする。管理画面は10秒、商品読取は60秒で初期画面へ戻す。外部API、DB、個人情報は使用しない。
- GitHubとVercelはCIAappから完全に分離する。

## バーコード読取

- カメラ映像は`navigator.mediaDevices.getUserMedia()`から取得し、HTTPS上でのみ開始する。
- ブラウザ標準の`BarcodeDetector`を優先し、非対応端末では同梱したZXing読取へ自動的に切り替える。通信先の外部CDNには依存しない。
- 初版の対応形式は`EAN-13 / EAN-8`とし、必要に応じて`Code 128 / QR`を設定で追加できる境界を保つ。
- 読取状態は`idle / requesting-permission / scanning / matched / unregistered / unavailable`として明示する。
- 同じコードの連続検知にはクールダウンを設ける。数量変更は買い物かごの操作で行い、カメラの連続フレームだけで意図せず増加させない。
- 商品台帳はバーコードをキーにしたローカルデータとして保持する。外部商品検索サービスは本番動作の必須条件にしない。
- 20〜29から始まるCIA MART用インストアコードは、EAN-13のチェックデジットを検証して登録する。

## 音声

- 音声再生は単一のAudioサービスを経由し、画面コンポーネントから直接Audio要素を乱立させない。
- 最初のユーザー操作でAudioContextを再開し、その後の操作音を許可する。
- 初版の効果音はWeb Audio APIで短い音を端末内生成し、外部音声ファイルへの依存を持たない。正式音源へ差し替える場合も同じAudioサービスを経由する。
- ミュート状態をアプリ内で保持できるようにし、音声が利用できない場合も視覚表示だけで操作を完了できるようにする。
- オフラインキャッシュにはアプリ本体、ローカル読取ライブラリ、静的素材を含める。将来商品画像を追加した場合も同じキャッシュ対象に含める。
- 画面遷移要求はネットワーク優先で最新版を取得し、通信失敗時だけ保存済み`index.html`へ戻す。ハッシュ付き静的資産はキャッシュ優先とし、サービスワーカー更新時は旧キャッシュを削除して新しい画面へ切り替える。

## 商品と取引

- 商品型は`barcode / name / price / taxRate / category / image / active`を持つ。
- 買い物かごはバーコードと数量を保持し、価格計算は商品台帳を参照する。
- 証拠およびカモフラージュ履歴は固定データとして保持する。通常セルフレジで新規取引を保存するかは、決済フロー確定後に別途決定する。
